# ZEKO CHARGE — starter project

واجهة عربية RTL لمتجر شحن ألعاب وخدمات رقمية، مصممة للعمل من الهاتف، مع نسخة عرض تفاعلية ومخطط قاعدة بيانات Supabase.

## الملفات
- `index.html` — هيكل المتجر.
- `styles.css` — التصميم المتجاوب والرسوم المتحركة.
- `app.js` — تفاعلات الواجهة التجريبية.
- `supabase-schema.sql` — جداول وصلاحيات قاعدة البيانات كبداية.

## مهم قبل الإطلاق
هذه نسخة بداية/عرض، وليست نظام شحن أو دفع حقيقياً بعد:
- الأسعار المعروضة غير مرتبطة بمورّد حي، وتظهر على أنها "حسب الباقة".
- طلبات الإيداع والطلبات ورسائل الدعم في الواجهة الحالية تحفظ في المتصفح الحالي فقط (localStorage)، ولا تظهر على أجهزة أخرى أو في لوحة إدارة حقيقية.
- تسجيل الدخول، الموافقة المالية، خصم الرصيد، الشحن التلقائي، رفع إثبات الدفع، وإرسال رسائل الدعم تحتاج ربطاً فعلياً بقاعدة البيانات والخادم.
- لا تستقبل أموالاً حقيقية بهذه النسخة، ولا تعتبر أي رصيد تجريبي مالاً قابلاً للسحب.
- لا تضع مفاتيح API الخاصة بمورّد الشحن أو Supabase `service_role` داخل `app.js` أو GitHub. مفتاح `anon` فقط هو المسموح للواجهة مع RLS صحيح.
- لا تمنح أي حساب دور `admin` من الواجهة العامة. عيّن المسؤول يدوياً من SQL Editor في مشروعك بعد إنشاء الحساب.

## تشغيل المعاينة
افتح `index.html` في متصفح أو انشر الملفات الثلاثة (`index.html`, `styles.css`, `app.js`) على استضافة صفحات ثابتة. الخطوط تأتي من Google Fonts؛ إذا لم يتوفر الإنترنت سيستخدم المتصفح خطاً بديلاً.

## إعداد قاعدة البيانات
1. أنشئ مشروع Supabase جديداً.
2. افتح SQL Editor.
3. راجع `supabase-schema.sql` ثم شغّله على مشروع جديد/فارغ.
4. أنشئ حسابك من نظام المصادقة عندما نضيف الربط.
5. بعد إنشاء الحساب، عيّن دور الإدارة يدوياً من SQL Editor باستخدام UUID الصحيح:
   `update public.profiles set role = 'admin' where id = 'YOUR-AUTH-USER-UUID';`
6. لا تنفذ هذا الأمر قبل التأكد من UUID حسابك، ولا تشارك مفاتيح سرية.

## ترتيب التنفيذ المقترح
1. نشر المعاينة على GitHub Pages والتأكد من الشكل.
2. ربط Supabase Auth والجداول مع اختبار الصلاحيات.
3. تنفيذ لوحة الإدارة الحقيقية وطلبات الإيداع مع مراجعة يدوية.
4. إعداد قناة دعم فعلية (بريد/Telegram/WhatsApp رسمي).
5. اختيار مزود شحن مناسب والتحقق من البلد والمنتجات والأسعار والحد الأدنى للدفع.
6. بناء API server-side آمن لا يحتفظ بمفتاح المورد في المتصفح.
7. اختبارات sandbox، ثم طلب تجريبي صغير بعد التأكد من المورد؛ لا تودع قبل ذلك.

## النشر على GitHub Pages
ارفع الملفات إلى جذر مستودع جديد، ثم من Settings → Pages اختر النشر من الفرع الرئيسي (main) والمجلد `/ (root)`. انتظر حتى ينشر الموقع. هذا ينشر واجهة المعاينة فقط، وليس خادماً أو قاعدة بيانات.

## محتويات الواجهة الحالية
- صفحة رئيسية متحركة وتصميم متجاوب.
- تصنيفات وبحث عن المنتجات.
- صفحات تفاصيل للمنتجات.
- محفظة تجريبية ونموذج إيداع تجريبي.
- قائمة طلبات تجريبية.
- نموذج فريق دعم تجريبي.
- معاينة لوحة الإدارة وسجلات التجربة.

## تنبيه
هذا المشروع نقطة انطلاق منظمة. لا يوجد ضمان أن أي مورد يقبل سوريا أو يدعم منتجات بعينها قبل التحقق المباشر من المورد.
